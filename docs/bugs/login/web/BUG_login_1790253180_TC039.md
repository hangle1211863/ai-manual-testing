# [BUG] Trang đăng nhập không ép chuyển hướng HTTP sang HTTPS, thiếu HSTS

## Thông tin chung
- **ID:** BUG_login_1790253180_TC039
- **Severity:** 🟠 Major
- **Priority:** P1
- **Nền tảng:** `web`
- **Môi trường:** Production/Demo dùng chung | Kiểm chứng bằng `curl` (độc lập trình duyệt, tránh Chrome tự nâng cấp HTTPS gây false positive) | — | —
- **Build / Version:** Không xác định (không có thông tin build hiển thị trên hệ thống)
- **Test case liên quan:** `CRM_LOGIN_TC_039`
- **REQ ID liên quan:** REQ-LOGIN-44
- **Test data đã dùng:** Không cần test data — kiểm chứng ở tầng giao thức HTTP
- **Ngày phát hiện:** 20-08-2026 (đo lần đầu theo tài liệu TC) — xác nhận lại 19-09-2026 và 24-09-2026 (2 lần trong phiên này)

## Steps to Reproduce
1. Gõ thẳng `http://crm.anhtester.com/admin/authentication` (giao thức **http** thuần, không phải https) vào một công cụ độc lập trình duyệt, VD:
   ```
   curl -I http://crm.anhtester.com/admin/authentication
   ```
2. Đọc mã trạng thái HTTP và các header trả về

## Expected Result
Theo `REQ-LOGIN-44` (PO chốt `AMB-LOGIN-20` ngày 19-09-2026): truy cập qua `http://` **bắt buộc** tự động chuyển hướng sang `https://` kèm header `Strict-Transport-Security` (HSTS). Cụ thể: request HTTP phải trả mã `301` hoặc `308` kèm header `Location: https://crm.anhtester.com/admin/authentication`, và bản HTTPS phải mang header `Strict-Transport-Security`.

## Actual Result
Request HTTP trả thẳng `200 OK`, phục vụ luôn nội dung trang qua kết nối không mã hoá — **không** có header `Location` (không chuyển hướng), **không** có header `Strict-Transport-Security`.

```

Connection: Keep-Alive
Keep-Alive: timeout=5, max=100
set-cookie: csrf_cookie_name=c3becc42ebe7e589af7485f92158e48f; expires=Thu, 24 Sep 2026 13:33:30 GMT; Max-Age=3660; path=/; HttpOnly; SameSite=Lax
Content-Type: text/html; charset=utf-8
set-cookie: sp_session=da1946d9584afffbc5601a8e49e1d1c7d7795124; expires=Thu, 24 Sep 2026 20:32:30 GMT; Max-Age=28800; path=/; HttpOnly; SameSite=Lax
Expires: Thu, 19 Nov 1981 08:52:00 GMT
Cache-Control: no-store, no-cache, must-revalidate
Pragma: no-cache
Content-Length: 4530

Server: LiteSpeed
```

## Evidence
- Error log / Response header (đo 24-09-2026, `curl -I http://crm.anhtester.com/admin/authentication`): xem khối log ở mục Actual Result phía trên
- Ảnh chụp trình duyệt không áp dụng cho bug này — kiểm chứng ở tầng giao thức HTTP, không quan sát được bằng mắt trên UI. Xem thêm ghi chú trong `CRM_LOGIN_TC_039` tại `docs/testcases/login/web/test_cases_login_web.md` dòng 108

## Ghi chú thêm
- **Tần suất tái hiện:** Luôn luôn (đo được ở 3 mốc thời gian độc lập: 20-08-2026, 19-09-2026, 24-09-2026 — cùng một kết quả)
- **Workaround:** Người dùng phải tự gõ `https://` vào thanh địa chỉ; không có cơ chế bảo vệ nào nếu người dùng gõ nhầm `http://` hoặc bấm vào liên kết cũ dùng `http://`
- **Nghi ngờ root cause:** Cấu hình server (LiteSpeed) hoặc virtual host chưa có rule redirect HTTP→HTTPS (thường cấu hình ở tầng web server, VD `.htaccess` rewrite rule hoặc listener HTTP riêng trả `301`) và chưa bật header HSTS ở tầng ứng dụng/server
- **Mức độ rủi ro bảo mật:** Người dùng vô tình truy cập qua `http://` sẽ gửi thông tin đăng nhập (email/mật khẩu) qua kênh không mã hoá, dễ bị tấn công man-in-the-middle đánh cắp thông tin đăng nhập trên mạng không tin cậy — đây là lý do xếp Priority P1 dù không chặn luồng chính khi người dùng tự gõ đúng `https://`
